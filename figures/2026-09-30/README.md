# 2026-09-30 — re-join solver, Phase 0 (#11)

This is an offline measurement: no Gazebo and no plant. It uses the re-join TPBVP (`PMPShootingSolver.solve_rejoin`) on
random off-plan states sampled along the 40 broad v2 plans, generated by `tools/rejoin_phase0.py`.
Cost **A** is the field cost the main planner uses. Cost **B** is minimum
effort. `T_w` is the re-join window in **physical time**.

| file | shows |
| --- | --- |
| `rejoin_phase0_regimes.png` | success vs `T_w` for the blend and plan guesses (Wilson 95% CIs), and heatmaps of `T_w` × feasibility margin (`T_w / t_min_wheel`) for A and B |
| `rejoin_phase0_examples.png` | sampled recoveries drawn with the robot footprint: scheduled (plan), actual start (red), target (blue outline), re-join path |

| `rejoin_phase0_{local300,plan300}.jsonl` | 300 problems each, blend vs plan guess (laptop) |
| `rejoin_phase0_vm2000.jsonl` | 2000 problems, plan guess, seed 1, `T_w` 0.5–10 s (VM, 34 s wall) |

What it establishes:
- **Failure is dominated by short windows, and that is physics.** A sideways
  offset needs turn-drive-turn under the wheel acceleration bound. On the
  2000-problem VM run, B fails 80% of problems at `T_w` in [0.3,1) s, 19% at [1,3) s and
  **1% at [3,10) s**. A fails 81% / 22% / 18% in the same bins.
- **B (min effort) is the teacher candidate**: median solve 4 ms (p90 37 ms)
  vs 83 ms for A. Almost all of its failures are a singular Jacobian at
  infeasible pins, not wrong answers.
- The plan guess lifts A from ~51% to 79% at 3–10 s (300-problem runs). B needs
  no help.
- Failure rises with `|e_xy|` above 0.4 m (B 55% there).

So the 36% library failure rate does **not** carry over to re-join, as long as `T_w >= 3 s`.
